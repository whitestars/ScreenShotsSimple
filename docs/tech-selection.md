# 截图工具框架 / 语言选型评估

## 1. 目标与约束

| 约束 | 内容 |
| --- | --- |
| 平台 | 仅 Windows，无需跨平台 |
| 形态 | 后台常驻 + 全局热键唤起，支持开机启动 |
| 轻量硬指标 | 无运行时依赖、单 exe 数 MB 量级、待机常驻内存 < 20MB |
| 首版功能 | 框选截图、六类标注、撤销、剪贴板 / PNG 输出、设置窗口、保存目录记忆、自启开关 |
| 团队背景 | 更熟悉 C# / .NET / WPF / WinForms |
| 明确不做 | 窗口边框识别、取色器、钉在桌面、长截图、OCR、录屏、自动更新、安装包 |

工作区为全新空目录，无历史架构与依赖负担，选型只受上述硬指标约束。

**关键矛盾**：「极致轻量」与「团队熟悉 WPF/WinForms」直接冲突。C# 的效率优势几乎全部来自 WPF/WinForms 框架，而这两个框架正是包体与内存超标的主因。本评估不回避该冲突，给出取舍结论。

## 2. 候选方案量化对比

> 下表体积与内存均为**经验估算**，不是实测结论。实测数据与验收结果见 [metrics.md](metrics.md)。

| 方案 | 单 exe 体积（估算） | 待机内存（估算） | 运行时依赖 | 满足硬指标 | 主要代价 |
| --- | --- | --- | --- | --- | --- |
| **C++17 + 原生 Win32 + GDI+ / WIC + 静态 CRT** | 约 0.3–2MB | 约 5–15MB | 无，零第三方库 | **是（主推）** | 消息循环、遮罩、工具栏、标注全部手写；多屏与 DPI 适配工作量大 |
| C# + NativeAOT + CsWin32 源生成 P/Invoke + 自绘 | 约 3–8MB | 约 10–20MB | 无 | 基本满足（备选） | 必须放弃 WPF/WinForms；窗口过程与消息循环仍需手写，XAML/控件经验无法复用 |
| C# + WPF / WinForms + self-contained 单文件 | 约 30–90MB | 40MB 以上 | 随包携带 .NET 运行时 | 否 | WPF 不支持 PublishTrimmed / NativeAOT，XAML 反射裁剪受限；开发最快但指标不达标 |
| Electron / Tauri + WebView2 | 数十 MB 起 | 明显超标 | 浏览器或 WebView2 运行时 | 否 | 常驻渲染进程；全屏遮罩跨 WebView 实现别扭 |
| Qt Widgets | 数十 MB | 偏高 | Qt 运行库 | 否 | 需附带运行库，为仅 Windows 场景引入不必要的跨平台抽象 |
| Python 打包 / AutoHotkey | 数十 MB | 偏高、启动慢 | 解释器 | 否 | 不适合长期常驻与复杂标注绘制 |
| Rust + windows-rs | 小 | 小 | 无 | 是 | 用户未选，生态与维护成本更高，本轮不纳入 |

补充：备选路线 NativeAOT 首次 `dotnet publish` 需要联网从 NuGet 获取 ILCompiler 包（后续可离线），主推路线全程零外部依赖。

## 3. 结论

**主推 C++17 + 原生 Win32 + GDI+ / WIC，`/MT` 静态 CRT。**

理由：

1. 它是唯一能干净同时满足「无运行时、单 exe 数 MB、待机 < 20MB」的方案。
2. 仅 Windows 平台，可以无条件使用系统原生 API（热键、剪贴板、GDI+、WIC、注册表），无需任何跨平台抽象。
3. 用户已明确表示愿意为轻量接受更长的开发周期。
4. 运行期零依赖：不分发 VC++ Redistributable、不分发 .NET、不分发任何 DLL；自启写 HKCU、热键用 `RegisterHotKey`，均不需要管理员权限。

**冲突取舍说明**：团队 C# 经验主要体现在 WPF/WinForms 框架上，这部分在硬指标下无法复用；能迁移的是工程组织、调试习惯与 Windows 平台概念（消息循环、句柄、DPI）。备选路线 NativeAOT 只保留 C# 语言语法，不保留框架，因此收益有限、代价不低。

**切换判据**：先按主推路线做出 PoC 并实测指标。若出现以下任一情况，再整体切换到 NativeAOT 路线（架构、模块划分、验收门槛不变，只替换实现层），避免中途混用两套技术栈：

- 实测待机内存或包体无法压到门槛内；
- 团队无法承担 Win32 手写 UI 的维护成本，且愿意放宽内存指标到 20MB 上沿。

### 实测验收

最终构建实测：单 exe **226304 字节（221 KB）**，静默后台待机 Working Set **11.34 MB**（设置窗口可见 11.95 MB），会话峰值 39.9~42.5 MB，会话结束 Private Bytes 回落到 2.1~2.4 MB、Working Set 回收至 0.38~1.77 MB。两次采样均通过 20MB 门槛，主推路线确认可行，无需切换备选方案。完整采样与环境说明见 [metrics.md](metrics.md)。

## 4. 开发 / 运行环境依赖

| 类别 | 结论 |
| --- | --- |
| 运行期 | **零依赖**。`/MT` 静态 CRT；`user32` / `gdi32` / `gdiplus` / `windowscodecs` 均为 Win10/11 系统 DLL |
| 开发期 | VS 2022（含「使用 C++ 的桌面开发」与 C++ CMake 组件）+ Windows 10/11 SDK |
| 不需要 | .NET SDK、vcpkg / NuGet / npm、Qt、Python、Docker、额外 SDK、管理员权限 |
| 可选 | 代码签名证书（避免 SmartScreen 提示），不影响构建 |

本机实测：VS 2022 Community、MSVC v143、Windows SDK 10.0.22621.0 / 10.0.26100.0、VS 自带 CMake 3.31.6-msvc6 与 Ninja 1.12.1 均已安装；CMake 未加入系统 PATH，需在 VS 的 Native Tools / Developer PowerShell 中构建，或使用其绝对路径。

## 5. 关键技术决策

| 主题 | 选择 | 权衡 |
| --- | --- | --- |
| 屏幕捕获 | `BitBlt` + `GetDC(NULL)` 抓虚拟桌面全屏 DIB | 依赖最少、兼容最好；无法稳定捕获部分 DirectX 全屏内容，首版接受，后续再评估 DXGI Desktop Duplication |
| 编码 | GDI+ PNG 编码器 / 系统 WIC，剪贴板 `CF_BITMAP` + PNG 格式 | 不引入 libpng、stb 等第三方库 |
| 遮罩 | 覆盖整个虚拟桌面的置顶无边框窗口 + 内存 DC 双缓冲 | 坐标系统一、跨屏框选简单；需处理负坐标与 DPI。实现上未使用分层窗口的 `UpdateLayeredWindow` 路径，以普通窗口双缓冲保证绘制可靠性 |
| 绘制 | GDI+ 自绘蒙层、标注、工具栏 | 无 UI 框架依赖，包体与内存可控 |
| 标注 | 命令对象 + 撤销栈；马赛克提交时做一次块平均 | 新增图形类型不改撤销栈与工具栏逻辑 |
| 自启 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 单值 + 开关 | 无需管理员权限、卸载干净；不写 HKLM、不做安装器 |

## 6. 轻量指标的设计保障

- **全屏位图按截图会话申请与释放**：一张 4K 32bpp 全屏 DIB 约 33MB，若常驻必然突破 20MB 门槛。会话结束（确认 / 保存 / 取消）立即释放 `HBITMAP`、`HDC` 与标注中间缓冲，待机态只保留消息循环、热键与托盘，不持有任何屏幕位图。这是能否达标的核心设计，也是 [metrics.md](metrics.md) 的重点检查项。
- 待机态纯消息循环阻塞等待，不轮询、不设定时器，CPU 接近零。
- `Release` 构建启用静态 CRT、体积优化与链接期优化；不引入第三方库。
- 句柄统一 RAII 配对释放，避免长期常驻导致句柄泄漏。
- 每增加一个功能模块复测一次体积与内存，防止后期功能把指标推回超标。
